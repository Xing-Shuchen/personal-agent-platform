# 划线纸书扫描件的本地提取与 EPUB 校正

版本：v0.1 · 探索实现规范

日期：2026-09-29

执行对象：Codex
样本目录：仓库内 `local-processing/`

## 2026-09-29 现场核验修订（优先于下文冲突条款）

用户看过第一轮可视化后明确调整目标：

- 完整页面预览先按 manifest 转正，再裁成单页有效区域；保留原始扫描件和原图坐标作为证据。
- 手画下划线可呈波浪形、有起伏和断裂。检测应保留曲线候选，短而难辨的笔画进入待核对，不能把印刷笔画静默认定为划线。
- 相邻且都画线的物理文字行合为一组；行级 OCR 和坐标仍保留。核验界面每组只展示一张同时包含文字与划线的裁图，不再并排展示 OCR 输入裁图和证据裁图。
- EPUB 在定位组内 OCR 对应区间后，向前、向后扩展到最近的逗号、句号、问号等标点边界，**只扩展、不收缩已匹配的 EPUB 区间**。补全可以包含照片外及未划线行的文字；因此输出必须并列保留照片 OCR、EPUB 匹配区间、扩展文本与来源标识，不把 EPUB 扩展冒称为视觉转录。
- EPUB 匹配可用整行 OCR 提供定位上下文，但标点扩展的起点必须是红线实际覆盖的字所对应的 EPUB 区间；不能把整行 OCR 都当作被划线范围。横向字位是估算值，应在界面中同时展示，供人工核对。
- 标点扩展优先在句末标点（句号、问号、叹号）截止；只有缺少句末标点时才用逗号、顿号等句中标点作为回退，且回退输出不带末尾句中标点。
- 有倾斜的页面须在最终文字检测、划线分割和 OCR 前校斜。manifest 记录校斜角度，输出坐标仍逆变换到原图。
- 手写批注加入独立证据流：保存区域裁图、源图坐标、机器 OCR 猜测和人工核对状态，不借 EPUB 替换手写内容。当前样本的手写区域由目视检查后写入 manifest；未配置的区域不会被假称为自动检出。
- 手画的 `「」` 角括号用于替代多行下划线；识别后与下划线走同一组级 OCR、EPUB 对齐和标点扩展流程，组内用 `mark_type` 区分证据。另存两端位置及跨行裁图；当前样本端点由目视写入 manifest，结果需核对。页面无下划线时，批注和角括号分支仍须执行。

上面的分组和标点扩展替代下文“每条输出固定为单行”和“EPUB 不得扩展到照片之外”的旧约束。`lines.jsonl` 继续作为行级证据，面向阅读的结果单位改为 `groups.jsonl`。

## 0. 给 Codex 的执行要求

在现有仓库中实现一个可运行、可逐图核验的本地实验流程，不再展开大范围模型调研，也不先建设训练数据集。

开始前读取仓库的 `AGENTS.md`、已有项目说明及依赖配置，检查 `local-processing/` 内的实际文件。沿用现有工程约定，不改造无关模块，不移动、重命名或覆盖用户原始扫描件和 EPUB。

先跑通真实样本上的最小端到端流程，再按失败案例改进。本文给出的算法是首选基线，不是假定已经在样本上验证成功的结论。没有可访问样本、缺少权重或运行环境不支持时，明确记录阻塞原因；不得用示例输出代替真实实验结果。

## 1. 目标与核心定义

给定按扫描顺序排列的一组纸书扫描件，以及用户提供的对应版本 EPUB，在本机：

1. 找出图中实际存在人工下划线的印刷文字行，保存整行在原图中的位置。
2. 对这些行逐行 OCR，保留原始识别结果。
3. 在 EPUB 中定位对应文字，在不突破图像可见范围的前提下提出或接受校正。
4. 独立识别印刷页码，利用连续扫描关系辅助消歧或推断，并标明来源。

**输出单位是照片中的一条物理文字行，不是句子、段落或下划线覆盖的字符片段。**

只要一行中有实际下划线，即使只划了该行的几个字，也提取该行全部可见印刷文字。同一行有多段下划线只输出一条行记录；连续多行分别输出，不合并为段落。不能因为语义连贯或 EPUB 中属于同一句，就收录未划线的相邻行。

“分割”在本文中指定位并裁出目标文字行的 ROI，不要求像素级语义分割。

## 2. 范围与不可违反的约束

### 2.1 本阶段范围

输入以高信噪比、基本无畸变的连续扫描页为主，可能包含少量目标页面以外的内容。优先支持中文横排印刷文字及其中的英文、数字、标点。

下划线与手画 `「」` 都进入阅读组，按 `mark_type` 区分；手写批注保留独立证据流。

不实现高亮识别、书页曲面展平、模型训练、阅读器集成或 PAP 正式服务集成。手写批注区域与 OCR 猜测按上方修订执行。复杂多栏、竖排等样本应显式记录为当前不支持或待核对，不静默输出错误结果。

### 2.2 硬约束

- **图像决定选哪些行。** EPUB 不能决定某行是否被划线，也不能生成不存在的划线行。
- **EPUB 只能校正已定位行。** 不得补全句子、段落、相邻行或照片外的内容；不得依据句意添加行尾标点。
- **原始证据不可覆盖。** 原图、原始 OCR、原始页码候选与机器校正建议分别保存。
- **不确定可以拒绝。** 无法可靠对齐时保留行坐标、裁图与 OCR，标记待核对，不强行替换。
- **全程本地处理。** 图片、OCR 文本和 EPUB 不发送到云服务，不调用在线 OCR、远程大模型或远程 EPUB 检索。
- **不训练模型。** 使用预训练 OCR 和传统视觉；人工核验数据用于评估，不以积累分割训练集作为交付前提。

允许对全页做文字区域检测，以便发现文字行几何；正文识别只对选中的划线行及其必要复识别裁图执行。页码候选是单独允许的识别分支。未划线行的检测框可以作为调试几何保存，但不得作为提取结果输出。

## 3. 输入、顺序与初始化检查

### 3.1 输入发现

至少支持 JPEG、PNG、单页 TIFF；发现多页 TIFF 时按帧展开。如果真实样本是 PDF，再增加按页栅格化的输入适配，记录源文件、页索引、渲染分辨率和坐标换算；不能把 PDF 文本层当作本次 OCR 的结果。

EPUB 必须来自用户提供的本地文件。默认只处理一组扫描件与一个 EPUB；发现多个 EPUB 时要求配置明确指定，不按文件名猜测书籍版本。不自动寻找其他版本，不处理加密或无法解析的内容。

扫描顺序优先取显式 manifest；没有 manifest 时，对输入文件做自然排序，生成可检查的顺序清单。不能用文件修改时间作为默认扫描顺序，也不能因页码 OCR 的结果而偷偷重排原始输入。扫描序号不是印刷页码。

自动发现输入时排除输出、缓存、模型权重及裁图目录，防止二次运行把生成物当作新扫描件。

### 3.2 页面清单

每页至少记录：

```text
page_id
source_file
source_sha256
source_page_index       # 普通图片为 null；多页容器使用 0-based 索引
scan_index              # 本批次扫描顺序，0-based
source_width / source_height
valid_page_roi          # 可为 null；使用原图坐标
processing_status
```

每张扫描页都必须进入页面清单，包括没有下划线、没有页码和处理失败的页面。重复文件应报告，不默认删除。

允许在 manifest 中覆盖有效页面 ROI、方向和顺序，用于排除扫描范围外的邻页残片。覆盖配置属于可追溯的人工输入，不能修改原文件。

### 3.3 初始化报告

先报告实际文件数量、格式、图像尺寸、EPUB 是否可解析、运行设备、可用 OCR 权重及潜在异常。发现缺失输入、歧义输入或不支持格式时给出具体路径和处理状态。

## 4. 技术路线与离线运行

首选流程：

```text
扫描页 → 输入解码／可选有效页面 ROI
              │
              ├─ PaddleOCR 文字检测 → 文字行几何
              ├─ OpenCV 下划线候选检测
              └─ 四角页码候选 → 局部 OCR
                         │
文字行几何 + 下划线候选 → 行关联／去重
                         ↓
                 目标整行裁图 → 逐行 OCR
                         ↓
EPUB → 文本索引 → 候选定位 → 局部对齐 → 边界检查
                         ↓
                逐行结果 + 原图证据 + 待核对项

扫描顺序 + 页码候选 → 连续页码检查／有来源的推断
```

OpenCV 的水平形态学线条提取作为下划线检测基线，结合文字行几何筛选；不能把“检测到水平线”直接等同于“检测到人工下划线”。参考官方形态学线条提取教程 [R1]。

PaddleOCR 的文字检测模块可独立输出文字区域；因此本项目应将全页 detection 与目标行 recognition 分离，而不是默认识别全页正文 [R2]。

OCR 适配器必须允许明确配置模型名、本地权重路径、设备与预处理参数。PaddleOCR 的识别模块提供独立 `TextRecognition` 接口及 `model_dir` 配置，可用于这一分路实现 [R3]。

首选现有环境可运行的一组 PP-OCR 预训练检测／识别模型。不依赖随版本变化的默认模型；首次跑通后固定实际模型名、权重哈希、PaddleOCR/PaddlePaddle 版本及完整依赖。没有现成环境时，可以从官方仍提供的 `PP-OCRv5_server_det` / `PP-OCRv5_server_rec` 组合启动；不为追求最新型号而阻塞实验。

优先依赖：Python、OpenCV、NumPy、Pillow、PaddleOCR/PaddlePaddle、EPUB/XML 解析库、RapidFuzz 或自实现编辑距离、pytest。沿用现有依赖管理；不引入数据库、任务队列、向量数据库或前端框架。

模型下载与正式处理分开。确需下载时由显式准备步骤执行；`run` 默认禁止网络，缺少本地权重时明确失败，不能触发隐式自动下载。提供不依赖 GPU 的可执行路径；性能优化后置。

## 5. 坐标与证据约定

所有对外坐标统一回到**源文件解码后、尚未旋转／缩放／裁剪的像素画布**。明确处理 EXIF，预览与坐标必须使用同一画布约定，不依赖浏览器自动旋转。

```text
原点：左上角
x：向右递增；y：向下递增
单位：原图像素
bbox：[x1, y1, x2, y2)，右／下边界不包含
裁图：image[y1:y2, x1:x2]
```

bbox 导出为整数，使用外包取整并限制在图像范围内；polygon 可以保留浮点数。执行旋转、缩放、ROI 裁剪或局部切块时，必须保存变换及逆变换，最终统一转换回原图。无变换时也记录单位变换。

对 PDF 等容器，另存页面栅格画布及其渲染信息，不把栅格像素坐标冒称为原 PDF 的坐标。

每条目标行至少保存：

```text
line_bbox / line_polygon       # 可见整行文字区域
underline_bboxes               # 一条或多条下划线证据
text_crop_bbox / text_crop     # OCR 输入区域及裁图
evidence_crop_bbox / evidence_crop
                               # 同时显示该行和下划线的核验图
```

证据图可包含少量周围背景甚至相邻行的边缘，但这些像素不因此成为被选中的正文。OCR 输入应限制在目标行；不能把多行证据图直接作为单行识别输入。

必须能通过任意一条结果在原图上重画行框与下划线框，并与保存的裁图对应。

## 6. 下划线检测与文字行关联

### 6.1 文字行几何

先对有效页面做文字检测，得到区域多边形与分数。按水平位置、纵向重叠、行高及间距整理为物理文字行。

检测框不保证天然就是完整的一行：同一行的多个片段应合理合并；跨越两行的框应局部分离或标记待核对。不能把相邻两行合成一条“目标行”，也不能把下划线本身的细长检测框当作正文文字行。

估计每页的典型行高和行间距，作为几何参数的尺度，不把所有阈值写成固定像素值。

### 6.2 下划线候选

在保留细笔迹的分辨率上尝试灰度化／二值化、多尺度水平形态学、连通域、线段合并。必要时增加小角度线段检测或在行下方搜索带中局部处理；不要求一开始实现所有备选算法。

候选至少保存 bbox、长度、厚度、方向、断裂或连续性特征、检测方法和筛选原因。允许短线、断线及轻微倾斜；不得通过“只接受跨越大半行的长线”绕开难例。

重点排查正文中的长横、脚注分隔线、表格线、页边框、印刷装饰线、`「」` 的短横及范围外残片。图像中无法可靠区分人工线与原有印刷线时，进入待核对，而不是声称已经识别出书写意图。

### 6.3 关联规则

结合候选与文字行的横向重叠、相对上下位置、局部行距和方向一致性判断归属。不得仅用无条件“最近的上方文字框”，也不得要求下划线像素必须与正文框相交。

一条线对应哪一行存在歧义时，保留候选及备选行，不同时把相邻两行当成已确认目标。只有下划线、没有对应文字框时，可围绕该位置局部重跑检测；仍失败则记录 `underline_without_textline`，不凭 EPUB 生成文字行。

同一行多条下划线合并为一条行记录，证据全部保留。输出顺序使用扫描顺序和页内几何阅读顺序，不用 EPUB 的匹配顺序改写图像记录顺序。

未确认候选保存到待核对或调试结果，不能因 EPUB 匹配失败而丢弃已从图像选中的目标行。

## 7. 逐行 OCR

从原始图像裁取目标行，保留行首、行尾及标点。优先使用未擦线的原图裁片，不先修复、重绘文字或删除与正文接触的笔迹。

每次识别保存原始文本、原始识别分数、模型信息、输入裁图路径和本次预处理。首次识别结果不可被复识别覆盖；需要调整边界、分辨率或对比度时，作为附加 attempt 保存。

每条划线行独立输出。OCR 返回空串或报错时仍保留该行及证据，状态为 `ocr_failed`。不能借 EPUB 找出“合理内容”来掩盖 OCR 失败。

复识别只能使用同一照片行的图像。不得把期望的 EPUB 文本作为提示或答案喂回识别流程，再把回填结果称为视觉验证。多次 OCR 一致只是辅助证据，不等于人工确认。

本阶段不要求字符级 bbox；以行级证据和保守校正规则控制范围。

## 8. EPUB 索引

按 OPF `spine` 读取章节，不能按 ZIP 文件列表或 XHTML 文件名字典序拼接。EPUB 的 `spine` 定义默认阅读顺序 [R4]。

保存两套文本：一套是保留原文字符、标点和结构来源的提取文本；另一套是仅用于检索的规范化文本。规范化可以包含 NFKC、空白处理和标点匹配策略，简繁转换默认关闭。

规范化文本与原文之间必须保留区间映射，不假设它们字符数相同。最终文字取自原文提取文本，不能从去标点的搜索文本生成结果。

正文提取应保留段落及内联文本顺序，排除脚本、样式和导航重复内容；特殊脚注、ruby、辅助内容需有明确处理策略并记录，不得把明显不同的正文与注释任意串接。当前不支持的结构应进入失败报告。

索引至少保存 EPUB 哈希、解析规则版本、spine 索引、href、原文提取文本及其哈希、段落边界、规范化映射。支持精确子串与字符 n-gram 召回，不需要向量检索。

位置的字符偏移统一定义为**该 href 对应的非规范化提取文本中的 Unicode 码点偏移**，不是 XHTML 字节偏移，也不是规范化文本偏移。区间使用 `[start, end)`。浏览器展示不能混用 UTF-16 下标。

DOM 路径、元素 ID 可作为辅助锚点；本阶段不要求生成 CFI。

## 9. EPUB 对齐、校正与边界保护

### 9.1 候选定位

先精确检索规范化行文本，再使用多个片段或 n-gram 召回候选窗口，在候选窗口内进行带插入、删除、替换操作的局部或半全局序列对齐。

对齐要覆盖这条 OCR 行的主体，不可只命中其中一小段常见短语，就宣称整行匹配成功。记录最佳和次佳候选、查询覆盖率、相似度、分差、编辑操作及边界风险。

候选可以保留上下文用于消歧，但上下文不是输出文字。

### 9.2 连续扫描约束

同页目标行及相邻扫描页的匹配位置可以提供阅读顺序约束。约束是辅助消歧，不是生成内容的依据。

只提取划线行，因此相邻两条结果之间可能跳过很多未划线文字，甚至整页。必须允许 EPUB 位置出现大间隔，不能要求两个匹配片段首尾相接。

默认把单调顺序作为软约束；碰到重复扫描、脚注位置差异或冲突时标记异常，不能为满足单调性强制选择明显较差的候选。页码分支失败不得阻断正文对齐。

### 9.3 校正边界

校正后的文本只能对应当前行在图中实际可见的印刷文字。允许输出不完整句子、半个词或没有句末标点的文本。

例如，当前可见行是“我们需要保留这一行”，未划线的下一行是“而不是扩展为整个段落。”，最终记录只能包含第一行。禁止调用“扩展到句号”“补全段落”等后处理。

区分三种缺字来源：图中存在而 OCR 漏掉；原图已裁掉或不可辨认；字出现在下一行。只有第一种可以在获得同一行图像支持后用 EPUB 补正，后两种不能补入。

校正时应产生可审查的编辑列表：

```text
operation: equal / substitute / insert / delete
ocr_span
epub_span
before / after
position: internal / leading / trailing
evidence: ocr_alignment / same_line_reocr / manual / unverified
```

其中 `insert` 表示 OCR 漏字、拟从 EPUB 加入；`delete` 表示 OCR 多识别内容。偏移必须能关联回相应原始字符串，不能混用规范化后的下标。

初始规则采用保守策略：候选唯一、主体覆盖充分、行边界无明显风险且只涉及有限内部替换时，可以按配置自动接受；涉及新增／删除字符、行首尾变化、裁切不完整或疑似版本差异时，默认待核对。标点也适用边界限制。

新增／删除或边界变化可通过同一行局部复识别提供补充证据，或由人工确认后接受。不能仅凭更高的 EPUB 相似度证明这些修改有视觉依据。记录哪些检查通过、哪些仍未验证。

### 9.4 状态与输出文本

| 状态 | 含义 | `corrected_text` |
|---|---|---|
| `matched` | 通过当前机器规则的唯一候选；不等同于人工确认正确 | 接受的对应 EPUB 文本 |
| `needs_review` | 候选歧义、边界风险、版本差异或修改缺少证据 | `null`，候选另存 |
| `unmatched` | 未找到可信 EPUB 候选 | `null` |
| `ocr_failed` | 目标行已找到，但 OCR 无有效结果 | `null` |

另存 `review_status`，区分 `unreviewed`、`confirmed`、`rejected`。机器运行结束不能自动设置为人工确认。

统一定义 `text_effective = corrected_text if accepted else ocr_raw`。消费方不得把 `candidate_text` 当成已确认原文。

相似度、候选分差、OCR 分数和几何分数分别记录；它们不是已经校准的正确率，不得合成为一个伪精确的“成功概率”。

## 10. 页码识别与连续性推断

页码处理是页面级独立分支，所有页面都运行，包括没有下划线的页面。

### 10.1 视觉候选

以有效页面的左上、右上、左下、右下为优先搜索区域。四角窗口大小可配置，结合整批页面重复布局调整。若四角始终无候选，可有限扩展到上／下页边中部；不能遍历正文数字后选一个最像页码的结果。

对短文本、阿拉伯数字及必要的罗马数字做局部识别，保存原始字符串、规范化值、bbox、区域位置、OCR 分数。所有数字都先是候选，不能直接认定为页码。

区分章节编号、脚注编号、年份和邻页残留数字。允许奇偶页位置不同，不默认所有页码都在同一角，也不只凭某个角落位置判断奇偶页。

### 10.2 连续扫描约束

在扫描顺序内寻找相互支持的候选。普通连续正文页默认期望每页 `+1`，但重复、漏扫、未编号页、插页、罗马数字前言及重新编号都必须能中断序列。

保守推断基线：只有左右两端都有可信视觉锚点、编号系列一致且数值差与扫描间隔一致时，才自动插值中间缺失页码。只有一个锚点或位于序列边缘时，可以给出待核对建议，不自动将外推值标为已识别。

```text
128, ?, 130 → 中间可以推断为 129；来源必须是 inferred
128, 130    → 报告跳号／可能缺页，不能把第二页强改为 129
没有可读页码 → 保持 unknown，不能从文件序号编造印刷页码
```

实际识别与推断字段分开：`observed_label/value`、`inferred_value`、`resolved_value`、`status`、`sequence_segment_id`、`inference_evidence`。有冲突时保存全部候选与原因。

推断结果不能伪造页码框：没有可靠识别到数字时，已解析页码的 bbox 为 `null`；可疑视觉候选框仍保留在候选列表。

EPUB 的 `page-list` 是可选结构，且其分页不一定来自这本纸书。只有明确确认对应纸书版本时，才把它作为附加校验；默认不建立纸书页码与 EPUB 的映射 [R5]。

## 12. 运行接口与交付目录

提供 Python CLI，以下是要求实现的接口形式；具体包目录沿用仓库约定：

```bash
python -m bookscan inspect --root local-processing
python -m bookscan run --config local-processing/config.yaml
python -m bookscan review --run local-processing/output/<run_id>
python -m bookscan evaluate --run local-processing/output/<run_id> \
  --ground-truth local-processing/ground-truth.jsonl
```

`inspect` 不运行 OCR，输出文件与环境清单、建议的顺序 manifest。`run` 执行处理；`review` 生成或刷新离线核验报告；`evaluate` 只根据明确提供的人工真值计算指标。

配置至少包括输入 root、EPUB 路径或唯一发现规则、manifest、输出目录、本地模型名与路径、设备、有效页面 ROI、检测／关联参数、对齐拒绝阈值、页码开关及搜索区域。所有初始阈值标为实验参数，不等同于准确率承诺。

```text
local-processing/
├── 用户现有扫描件与 EPUB       # 保持现有位置，不要求重排
├── config.yaml
├── manifest.json
├── ground-truth.jsonl         # 人工核验后生成；不是训练 mask 数据集
└── output/<run_id>/
    ├── run.json               # 环境、配置、输入／权重哈希、耗时
    ├── manifest.resolved.json
    ├── pages.jsonl
    ├── lines.jsonl
    ├── review_candidates.jsonl
    ├── failures.jsonl
    ├── crops/
    ├── overlays/
    ├── debug/
    ├── review.html
    ├── review-decisions.jsonl
    ├── metrics.json
    └── experiment-report.md
```

没有人工真值时可以不生成数值指标，但报告必须写明“未评估”，不得显示虚构准确率。

运行目录不可覆盖原图或前次实验。支持按页重跑和分阶段缓存；缓存键包含输入哈希、模型、代码／算法版本、配置及上游输出。改变 EPUB 或对齐参数不应强制重跑视觉步骤，改变 ROI 或检测结果必须使相关下游缓存失效。

逐页记录错误，单页失败不阻塞其他可处理页面；最终返回可区分完全成功、部分失败和初始化失败的退出码。异常空输出不能当作成功。

## 13. 人工核验与实验指标

### 13.1 离线核验报告

生成无需外部资源的 HTML 报告，至少能查看完整页面、放大原图、显示文字行框／下划线框、打开单行与证据裁图，并对比 OCR、EPUB 候选、接受的校正及编辑差异。

必须能查看零检测页面和被拒绝候选，不能只展示成功结果。页码区域、视觉读数、推断值及依据单独展示。

人工决定保存为 sidecar，不覆盖机器结果；记录确认、误收、错行、裁图问题、漏检行、新的人工转录和 EPUB 越界等。最小实现可以通过编辑 JSONL 记录漏检 bbox，不要求建设完整标注平台；但必须有添加漏检行的入口或清晰操作说明。

### 13.2 真值与统计口径

人工先完整查看每页，再标记所有真实下划线行。只检查模型已输出的裁图，无法用于统计漏检率。

评估标注只需行级框、是否实际有下划线、可见文字转录、必要的 EPUB 对应片段及页码；不要求逐像素 mask。边界无法判断的样本单独标为歧义，报告其数量，不强造唯一真值。

| 维度 | 必须报告的内容 |
|---|---|
| 行选择 | 行级 precision / recall / F1；漏检、误收、重复输出、错行关联数 |
| 裁图与坐标 | 完整行覆盖、混入邻行、截断文字、坐标越界及回投错误 |
| OCR | 在正确选中且正确裁图的行上的 CER；空串、失败单列 |
| EPUB | 定位正确率、校正后 CER、误改数、越界补字数、未划线邻行混入数 |
| 自动接受 | 接受覆盖率与已接受结果正确率分别报告，并注明审核分母 |
| 页码 | 实际识别、推断、未知、冲突分别统计；已识别与推断的正确率分开 |
| 成本 | 各阶段耗时、每页耗时、运行设备；冷启动与缓存运行分开 |

行级几何评价采用一对一匹配，公开匹配规则。大框覆盖多行不能同时算多个真阳性；同一行的重复输出不能重复计分。分母为零时使用 `null` 或 N/A，不显示 100%。

OCR 质量和 EPUB 校正质量使用人工可见行转录作为真值，不能直接把 EPUB 候选当作照片真值。需要同时报告条件指标和端到端失败数量，避免只在成功案例上给出好看的分数。

第一轮记录真实错误，再提出下一轮参数或方法调整。不设置未经实测的 99%／95% 门槛。可建立小型固定回归集；用过的调参样本与未参与调参的核验样本分开说明，样本太少则不声称泛化能力。

## 14. 必须覆盖的测试与失败分类

至少覆盖以下行为；真实样本没有的场景可用合成小图和文本做单元测试，但不能把合成测试指标冒称为实书效果。

| 测试场景 | 期望行为 |
|---|---|
| 整页无下划线，或只有 `「」` | 不输出已选划线行；页面仍有处理记录 |
| 一行部分划线；同一行两段划线 | 返回该可见整行一次，保留全部下划线证据 |
| 连续三行中只有第一、第三行划线 | 输出两条，不收录中间行，不拼成段落 |
| 短线、断线、轻微倾斜、正文接触 | 检测或明确记录失败，不能仅按长线样本设计 |
| 印刷横线、表格线、脚注线、邻页残片 | 不直接等同人工下划线；歧义可拒绝 |
| OCR 漏字；行首／行尾被裁切；下行才有标点 | 区分可见漏字与不可见内容，禁止自动扩句 |
| EPUB 相同短句出现多次；无对应内容 | 保留候选或 unmatched，不强配 |
| 全半角、组合字符、规范化长度变化 | 原文偏移和截取文本一致，不因规范化错位 |
| 连续页码、缺失页码、跳号、重复、重新编号 | 来源区分正确，异常不强改，推断不伪造 bbox |
| 裁剪、缩放、旋转后的坐标 | 逆变换回到原图正确，裁图不越界 |
| 无本地模型、坏文件、禁止联网 | 明确报错，无隐式下载或伪造结果 |
| 同输入配置重复运行；更换 EPUB 后重跑 | 结果结构可复现，缓存正确失效，原始文件不变 |

失败原因至少区分：`underline_missed`、`false_underline`、`wrong_line_association`、`line_split_or_merge_error`、`crop_truncated`、`ocr_error`、`epub_unmatched`、`epub_ambiguous`、`epub_wrong_location`、`epub_overreach`、`edition_mismatch`、`page_number_error`、`sequence_conflict`、`coordinate_error`、`unsupported_input`。

真实样本整体验证失败时也应交付代码、证据与报告，而不是通过删除失败页或扩大文本范围让结果看似通过。

## 15. 实施顺序与完成定义

**M1：输入与行选择。** 完成文件检查、顺序清单、文字检测、下划线候选、行关联、裁图与原图 overlay。先逐图检查是否选对行；暂不利用 EPUB 改进选择结果。

**M2：逐行 OCR 与受限校正。** 完成原始 OCR 保存、EPUB 索引、候选对齐、编辑记录、边界保护和拒绝状态。优先保证不存在静默扩句、跨行补字和原始 OCR 被覆盖的问题。

**M3：页码分支。** 完成四角候选、布局与序列消歧、可追溯插值和异常报告。没有页码的扫描仍能完成正文流程。

**M4：核验与实验结论。** 交付 CLI、配置示例、环境／模型准备说明、测试、离线核验页面、实际样本输出与实验报告。人工真值尚未提供时，清楚标明待完成的核验，不伪造人工结果。

工程完成不等于准确率已达到正式使用标准。完成的最低要求是：一条命令可复现处理；每个输入有状态；每条选中行可回到原图；OCR 与校正不混淆；EPUB 无匹配时仍保留证据；页码识别和推断可区分；失败可查看、可归因；无云调用和定制训练。

实验报告必须回答：实际用了什么输入、版本和参数；找到哪些行、错在哪里；OCR 与 EPUB 分别改善或损坏了什么；页码识别与推断有何效果；哪些结果尚未人工核对；下一轮最值得修改的少数问题是什么。不要以“继续训练一个大模型”作为默认结论。
