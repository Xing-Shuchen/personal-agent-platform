# Local changes to vendored source

Source hashes and original paths are in `UPSTREAM.md`.

- `SeatPool.ts`, `pathfinding.ts`, and `TiledMapRenderer.ts` are unchanged.
- `Camera.ts` adds an immediate target snap for the system reduced-motion setting.
- `CharacterSprite.ts` documents both supported frame producers and freezes its current animation on frame zero in reduced-motion mode.
- `glRecovery.ts` accepts a scene-lifetime retry budget so repeated canvas rebuilds cannot reset the three-attempt limit.
- `DeskScreen.ts` requires theme supplied monitor GIDs and uses a one tile animation region for the original owned theme. MD's LimeZu GID fallback was removed.
- `cast.ts` changes the import path, caches generated textures by recipe version, and registers eight original specialist appearances. Cast display names are never used as specialist names.
- `portraitArt.ts` changes the local import path and adds eight original palette, hair, clothing and accessory recipes to the 15 upstream procedural recipes.
- `SpriteAdapter.ts` is a project rewrite of MD's optional sheet adapter. It requires a declared source and license, explicit direction groups, and validates geometry before texture extraction. No external sheet is bundled.
- `Character.ts` was rewritten to take a scene entity ID, display name, validated map, and pure visual presentation. It retains sprite movement, pathfinding, seated crop, labels and transient success graphics while removing MD business logic, idle stories and command center behavior. Reduced motion places characters at their seats and suppresses transient success graphics. Nameplates wrap within an 84-pixel scene width so long session labels remain distinguishable at adjacent desks during camera focus.
- `ToolBubble.ts` keeps the bounded Pixi bubble layout from pinned MD source. Its public display method accepts only a validated current tool name from FloorState; generic text and target display entry points are no longer public. No target path, tool arguments, result, hidden reasoning or unverified summary is passed. The scene hides it when the run ends or becomes stale. Exact `read_file` and `write_file` icon mappings and reduced-motion snap are local changes. The upstream file also records ancestry from `shahar061/the-office` under the retained ISC notice.
- `ThoughtBubble.ts` keeps the pinned MD cloud layout, replacing MD design-token imports with owned colors. Its only active display entry point accepts a sourced, byte-bounded `FloorState.work.summary`; the scene shows it only for a fresh running session and hides it while a verified tool bubble is shown. The upstream thinking-dots path is disabled because no hidden reasoning or unsourced activity may be inferred. Reduced motion snaps its fade to the final frame.
- `MessageEnvelope.ts` keeps the pinned MD envelope animation but removes hive speech acts, human escalation and MD design tokens. Its tint comes from the three `FloorHandoff.kind` values. `HandoffLedger` admits only a new, unexpired, sourced handoff whose endpoints are fresh and visible on the current scene page; first snapshots, scene rebuilds, hidden pages, duplicates and denied access do not create a flight. The target Gateway currently supplies no verified handoff events, so this remains inactive in the real office.
- `OfficeScene.tsx`, `appearance.ts`, `theme.ts`, `stateMapping/*`, and the owned map/atlas are project code. They replace MD's store, hive, terminal and restricted art dependencies. Page changes place the newly visible sessions directly at their assigned seats; only genuinely new arrivals on the same page walk in from the shared entrance.
