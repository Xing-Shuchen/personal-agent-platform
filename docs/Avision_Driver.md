## 目标与范围

用户拥有一台虹光 Avision FB2080E 平板扫描仪，希望在 Ubuntu 上可靠扫描纸质书，至少保留基本扫描参数控制、原图保存，以及人工翻页后的连续扫描。机身按键、数字显示、灯控与休眠属于第二阶段。扫描得到的原图将用于划线识别、OCR 和 EPUB 对齐，但本轮不要扩展为 OCR 项目。

优先修通现有 Linux 扫描路径，不要直接开始移植整套 Windows DLL、重写驱动或重做原厂界面。

## 已有证据：先核对，不要重新假设

第一版原始日志的 system.txt 记录：

- 日志时间：2026-10-03T15:54:22Z。
- 环境自报 Ubuntu 26.04.1 LTS，x86_64，Effective UID 1000。该信息不足以证明诊断进程拥有宿主机的完整设备视图。
- 安装包信息：libsane-common、libsane1:amd64、sane-utils 均为 1.4.0-1ubuntu1。
- 实际 scanimage --version 输出：`scanimage (sane-backends) 1.2.1-debian; backend version 1.2.1`。

同一批日志还记录：

- `lsusb -d 0638:0a84` 标准输出为空，退出码 1；脚本的 USB sysfs 匹配结果为空。
- Avision 后端库加载并初始化，最终 `sane_get_devices: found 0 devices`。
- 默认枚举仅发现两个 v4l 摄像头条目，不是 FB2080E。
- Access denied 对应其他 USB ID，没有一条对应 0638:0a84；不能据此判定扫描仪权限错误。
- `Trying to find USB device 0638 0a84` 是搜索条目，不是已发现设备。
- 旧版临时配置缺少 dll.d 导致 opendir 警告，但后端随后成功加载，不能把该警告当主因。

当前判断边界：只能说预期 USB ID 未出现在第一版脚本的可见范围中。不能据此证明扫描仪坏了、驱动不支持、用户忘记插线，或一定存在容器隔离。也不能因包版本与运行版本不一致，就认定它解释了 USB ID 缺失。

## 前序静态分析线索：不是硬件通过清单

前序报告称 Windows INF 中的预期设备 ID 为 0638:0a84，核心 DLL 为 FB2080.dll / FB2080_x64.dll，涉及 usbscan.sys 和用户态设备逻辑；曾在 SANE avision 上游看到同型号同 ID，描述等级为 basic。需要做兼容性决定时，重新核对原 INF、实际加载后端及对应版本源码，不要把上游 master 支持等同于本机运行版本已正常工作。

前序报告还提供 SetScanParameter、StartScan、ReadScan、StopScan、按键、灯控与数字显示相关接口，以及部分 READ/SEND 命令的静态线索。DLL 可能包含多型号共享分支；函数存在不证明本型号支持。未验证前不要据此向真机发送自定义 USB 命令。

## 第一阶段：直接继续诊断

先阅读本文件、原始日志、证据摘录和 v2 脚本。审查脚本后再运行。先用普通用户，不要默认给整个 Codex 或脚本 sudo 权限。

1. 确认执行位置及设备可见性。辨别连接扫描仪的 Ubuntu 宿主机、另一台远程主机、虚拟机、容器与受限执行环境。查看完整 USB 清单与 sysfs，而不是只筛选预期 ID。
2. 在环境允许且脚本检查通过后运行 v2。它的预期用途是记录设备清单、可执行文件位置、库加载路径、环境差异和 SANE 枚举，不请求实际图像扫描。打开设备仍可能初始化设备，不能描述为完全零状态变化。
3. 查看 `type -a scanimage`、实际文件/符号链接及包归属，核对加载的 SANE 库，检查 PATH、LD_LIBRARY_PATH、LD_PRELOAD、SANE_CONFIG_DIR 等相关配置。将默认调用与清理相关覆盖变量后的 /usr/bin/scanimage 比较，不要打印整份环境变量或泄露令牌。
4. USB 清单仍找不到目标时，借助宿主机终端的 USB 热插拔事件识别新出现的设备及实际 ID。只在需要用户物理插拔或执行获准的宿主机命令时提出具体操作；不要把沙箱的设备缺失当成宿主机结果，也不要绕过沙箱或审批机制。
5. 实际目标设备出现后再查精确设备节点权限、udev 与 SANE 后端打开情况。对其他 USB 设备的拒绝访问不做泛化修复。

若受限于当前执行环境，只完成可执行的静态分析、日志解读和脚本审查，并明确给出最小的宿主机操作；不要伪称已经完成硬件验证。

在证据明确后做最小、可回滚的修复。可能涉及路径混用、包文件、后端配置或针对准确设备的权限规则；不要先入为主选一种。
